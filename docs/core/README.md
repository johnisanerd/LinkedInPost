# Core design documents

Keep one authoritative document per design scope. Create vision, system
architecture, and module design documents here when the project's requirements
are known; do not fill them with invented product decisions.

- State intended behavior, boundaries, interfaces, ownership, and invariants.
- Register each source in ledgers/documents using its template.
- Put delivery status in feature/backlog records and dated evidence in research.
- Update the owning design in the same change that deliberately changes behavior.
- Link decisions and open gaps; do not copy their mutable status into the design.

For an existing project, retain its established design locations and register
them rather than moving everything into this directory.
